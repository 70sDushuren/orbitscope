# OrbitScope 需求分析

> 版本 0.1 · 2026-11-16 · 状态:草案(待评审)

## 1. 用户与使用场景

| 角色 | 场景 |
|------|------|
| 航天爱好者 | 打开网页看当前 LEO 上有多少物体、它们在哪里、某颗卫星的轨迹 |
| 学生/研究者 | 按高度/尺寸/类型筛选物体,导出数据做统计(如碎片高度分布) |
| 开发者 | 通过 REST/WebSocket API 获取过滤后的实时位置,接入自己的应用 |
| 运维者 | 在服务器上长期运行,定时更新数据,多人同时访问 |

## 2. 术语

- **GP / OMM / TLE**:通用摄动轨道根数及其两种表示(CCSDS OMM、两行根数)。
- **SGP4/SDP4**:与 GP 根数配套的解析外推模型;周期 ≥ 225 分钟的深空物体自动使用 SDP4。
- **TEME**:SGP4 输出的坐标系(真赤道平春分点)。
- **RCS**:雷达截面积(m²)。
- **近地点/远地点高度**:相对地球赤道半径(6378.137 km)的高度。
- **瞬时高度**:物体当前位置相对 WGS84 椭球的大地高。
- **NORAD 编号**:编目号(注意:即将超过 5 位数,必须支持 9 位编号 → 优先使用 OMM/JSON 而非 TLE)。

## 5. 尺寸过滤的说明(重要)

公开数据中**没有物体直径**。本程序的"尺寸"是由 RCS 推出的**等效直径估算**:

1. 若有数值 RCS(m²,来自 CelesTrak SATCAT):在光学区近似 `RCS ≈ π·d²/4` ⇒ `d ≈ 2·√(RCS/π)`。
   - 10 cm 对应 RCS ≈ 0.00785 m²。
   - 后续可替换为 NASA 尺寸估算模型(SEM)的完整曲线以覆盖瑞利/谐振区。
2. 若只有 Space-Track 分档:SMALL(< 0.1 m² ⇒ d < ~36 cm)、MEDIUM(0.1–1 m² ⇒ ~36–113 cm)、LARGE(> 1 m² ⇒ > ~113 cm)。
   该分档转换为**直径区间**;当门限落在区间内部(例如 10 cm 落在 SMALL 区间内)时,结果为"不确定",按"未知尺寸策略"处理。
3. 若都没有:尺寸未知,按"未知尺寸策略"处理。

UI 与导出数据中都需带上 `size_source`(numeric_rcs / rcs_category / unknown)字段,避免误导。

## 6. 约束与假设

- 用户若要获取含碎片的完整编目,需自行注册 Space-Track 账号。
- 程序不做雷达/光学观测,不产生新的定轨数据,只消费公开 GP 数据。
- 运行环境可访问 `www.space-track.org` 和/或 `celestrak.org`;否则只能用本地文件。

## 7. 验收用例(摘要)

1. 无账号首次启动 → 自动从 CelesTrak 下载 → 浏览器看到 LEO 物体在地球上运动。
2. 配置 Space-Track 账号 → 物体总数显著增加(含碎片)→ 1 小时内不会重复请求全量。
3. 把高度改为 400–450 km → 1 s 内只剩该壳层物体(如空间站附近壳层)。
4. 尺寸门限改为 1 m、未知尺寸 = 排除 → 只剩 LARGE / 数值 RCS ≥ 0.785 m² 的物体。
5. 拔网线后重启 → 从缓存启动,状态栏提示数据龄期。
6. `orbitscope show 25544` → 输出 ISS 当前经纬高,与公开跟踪网站结果相差 < 几十 km。
